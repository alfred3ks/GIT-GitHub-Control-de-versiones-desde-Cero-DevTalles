### ¿Porque nos interesa un control de versiones?

Un sistema de control de vesiones es una heramienta que guarda el historial de cambios de un proyecto a lo largo del tiempo.

Nuestros proyectos o carpetas son conocidos como repositorios, dentro de estos se van haciendo los cambios, pueden ser grandes, pequeñós, se recomienda pequeños, se van creando ciertos puntos en el tiempo que se van llamando commits.

Nos interesa un sistema de control de versiones porque nos permite guardar y controlar la evolución de un proyecto a lo largo del tiempo.

Podemos pensar de un sistema de control de versiones como una máquina en el tiempo donde:

- Cada cambio queda registrado, que se modifico, cuando y por quien.
- Se puede volver a cualquier punto anterior del proyecto en segundos.

Con un sistema como Git podemos:

- Guardar un historial de cambios: saber qué se modificó, cuándo y quién lo hizo.
- Volver atrás: recuperar una versión anterior si algo deja de funcionar.
- Crear ramas: trabajar en nuevas funcionalidades sin modificar directamente la versión principal.
- Trabajar en equipo: varias personas pueden trabajar sobre el mismo proyecto y combinar sus cambios.
- Evitar perder trabajo: los cambios quedan registrados y podemos recuperar versiones anteriores.
- Comparar cambios: podemos ver exactamente qué líneas se han añadido, eliminado o modificado.

En resumen: Git nos permite tener un historial controlado de nuestro proyecto, facilitando tanto el desarrollo individual como el trabajo en equipo.

#### Que pasa si no usamos git/control de versiones:

- Se pierde trabajo sin forma de recuperarlo,
- Dos personas editan el mismo archivo y una sobrescribe a la otra,
- Nadie sabe que cambio, cuando, ni porque.
- Miedo a tocar algo que ya funciona, por si se rompe.

En la era de IA un sistema de control de versiones es mucho mas importante que nunca.
